# RoadMind · 多智能体架构设计

> 版本：v1.0（2026-09-26）
> 技术栈：**Python 3.11 + LangGraph**｜视频感知（YOLO + ByteTrack）｜向量检索（chromadb）｜Web（FastAPI + 前端）
> 配套文档：`TEAM-ROLES.md`（分工与排期）、`EXECUTION-PLAN.md`（方案）

---

## 1. 架构总览

RoadMind 是一个**多智能体协作**系统，核心职责：
1. 识别行车记录仪/事故现场视频，抽取结构化场景；
2. 结合交规法条与典型案例，输出**责任认定建议**（辅助交警，非裁决）；
3. 事故发生时即时输出**应急处置方案**（服务车主，防止恶化）。

三个能力由**多个专职智能体**承载，由 LangGraph 状态图编排协同。

```
                     ┌────────────────────────────┐
                     │         Web 前端 (M6)       │
                     │  车主端 / 交警端 / 可视化    │
                     └──────────────┬─────────────┘
                                    │ REST / WebSocket
                     ┌──────────────▼─────────────┐
                     │   FastAPI 后端 + 任务队列    │
                     │         (M5·part)          │
                     └──────────────┬─────────────┘
                                    │
            ┌───────────────────────▼───────────────────────┐
            │         LangGraph 多智能体编排层 (M5)          │
            │                                                 │
            │  ┌──────────┐   ┌──────────┐   ┌──────────┐    │
            │  │ M1 视频   │──▶│ M3 责任   │   │ M4 应急   │   │
            │  │ 感知智能体 │   │ 判定智能体│◀─▶│ 方案智能体│   │
            │  └──────────┘   └────▲─────┘   └──────────┘    │
            │                      │ RAG                     │
            │                ┌─────┴────────────────┐        │
            │                │ M2 规则+案例检索(RAG) │        │
            │                └──────────────────────┘        │
            └─────────────────────────────────────────────────┘

                          ┌─────────▼─────────┐
                          │  MoMA 平台模型服务 │
                          └───────────────────┘
```

## 2. 智能体划分

| 智能体 | 对应模块 | 输入 | 输出 | 职责 |
|--------|---------|------|------|------|
| **感知智能体** | M1 | 视频文件/帧流 | 场景 JSON | 目标检测、轨迹提取、碰撞点与关键帧、道路/信号要素识别 |
| **判定智能体** | M3 | 场景 JSON + RAG 检索结果 | 责任认定 JSON | 要件分解→比对规则→责任归属+法律依据+理由+置信度 |
| **应急智能体** | M4 | 场景 JSON（事故类型/伤亡/车辆状态） | 应急方案 JSON | 按事故类型生成分级处置步骤（报警/警示/撤离/急救/保险） |
| **检索服务（RAG）** | M2 | 查询要素 | 相关法条+相似案例 | 法条/裁判文书向量检索，为判定提供依据 |

> 判定智能体与应急智能体**可并行**：判定侧重「事后责任」，应急侧重「当下处置」。编排层在感知完成后并行触发两者。

## 3. LangGraph 状态图设计

### 3.1 State Schema（共享状态）

```python
from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class RoadMindState(TypedDict):
    video_id: str
    # M1 感知结果
    scene: dict | None
    # M3 判定结果
    judgment: dict | None
    # M4 应急结果
    response: dict | None
    # M2 检索增强
    retrieved: list[dict]
    # 汇聚给前端
    result: dict | None
    error: str | None
```

### 3.2 图结构

```
START
  │
  ▼
 感知节点 perceive        (M1: 视频 → scene)
  │
  ├──────────────► 条件判断
  │                 ├─ scene 有效  ──► 并行分支
  │                 │                   ├─ 判定节点 judge (M3 + M2 RAG)
  │                 │                   └─ 应急节点 respond (M4)
  │                 └─ scene 无效/(降级) ─► 人工补录入口 → 判定节点
  │
  ├──────────────► 汇聚节点 aggregate (合并 result)
  │
  ▼
 END
```

### 3.3 关键设计点

- **状态单例传递**：各节点读写共享 `RoadMindState`，避免重复计算。
- **并行分支**：LangGraph 的 `Send` / fan-out 让 judge 与 respond 并行，缩短响应时延。
- **条件边降级**：当感知置信度过低或无检测时，走「文字补录现场要素」路径，保证多智能体推理可继续（对齐"硬核可选"原则）。
- **人工护栏**：判定输出带 `confidence` 与 `reasoning`，前端明确标注为"辅助研判建议，非最终裁定"。

## 4. 模块组件设计

### 4.1 M1 视频感知（P3）
- 抽帧：关键帧采样（避免全量处理，控制成本）
- 检测：YOLOv8 / YOLOv11 行人、机动车、非机动车、信号灯
- 追踪：ByteTrack 关联轨迹 → 提取速度、碰撞点、碰撞时刻
- 输出：`scene` JSON（结构见 `TEAM-ROLES.md` §5）

### 4.2 M2 RAG（P2 服务 + P3 数据处理，P1 数据）
- 数据源：《道交法》《实施条例》、地方细则、公开裁判文书
- 切分：按条文/判决说理段切分
- Embedding → chromadb 向量库
- 检索：按事故场景要素（类型/过错/路况）召回 top-k

### 4.3 M3 判定智能体（P3）
- 提示词工程：角色设定（"交警辅助研判助手"）+ 要件清单 + 检索上下文 + 场景
- 推理链：分解要件 → 逐项比对 → 责任归属 → 引用法条 → 输出结构化 JSON
- 结构：`responsibility / split / basis / reasoning / confidence`

### 4.4 M4 应急智能体（P3）
- 规则基（场景画像→处置模板）+ LLM 润色
- 分级：紧急（伤亡/起火/漏油优先）→ 一般（普通碰撞）
- 输出：分步 `steps` + 保险指引 + 证据固定建议

### 4.5 M5 后端与 API（P2）
- FastAPI 端点：上传、任务状态、结果查询；WebSocket 进度推送
- 任务队列：文件上传后异步处理，避免长请求阻塞
- 鉴权：交警端/车主端角色区分

### 4.6 M6 Web 前端（P4）
- 车主端：上传视频 → 实时进度 → 风险提示（立即处置）+ 应急步骤 + 责任预判概览 + 保险报案指引
- 交警端：案件列表 → 责任认定详情（检测可视化/时间轴/证据清单）→ 认定书草稿导出
- 可视化：检测框叠加、关键帧回放、责任原因标注、置信度条

## 5. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 编排 | LangGraph | 状态图式多智能体，支持并行/条件边/状态单例 |
| 检测 | YOLO + ByteTrack | 成熟、可在本地 GPU/CPU 跑，成本可控 |
| 向量库 | chromadb / faiss | 轻量、离线可部署 |
| 后端 | FastAPI + Uvicorn | 异步、WebSocket、与 Python 生态一致 |
| 前端 | Vue3 / React + ECharts | 可视化 + 双视角路由 |
| 模型网关 | MoMA 平台 | 统一接入 LLM 与视视觉模型鉴权/配额 |

## 6. 部署形态（D1～D11 目标）

- 单机/单服务部署：FastAPI 承载 API + LangGraph，视频处理子进程/任务队列
- 模型：本地推理（检测）+ 平台 LLM（判定/应急润色）
- 交付：`docker-compose` 一键起服务 + 演示脚本

---

## 7. 安全与合规

- 判定为**辅助建议**，明确免责边界，不替代交警裁决
- 视频/证据数据本地或合规存储，最小化采集；涉及个人信息脱敏
- API 角色鉴权，车主/交警数据隔离

---

## 8. 演进路径

- **Phase A（11 天基础版）**：上传视频→建议；关键帧抽帧本地检测；规则 + 少量案例 RAG
- **Phase B（后续）**：实时流式接入、多车轨迹精细碰撞重建、更完整法条库、责任认定置信评估
