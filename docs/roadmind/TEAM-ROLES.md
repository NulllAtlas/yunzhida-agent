# RoadMind · 多智能体交通事故辅助判定 — 团队分工与 11 天排期

> 版本：v1.1（2026-09-26 修订为两阶段定位）
> 技术栈：**Python + LangGraph**（多智能体编排）｜ **Web 双视角界面**（交警端 + 车主端）｜ 完整视频感知放迭代阶段
> 团队：4 人（P1–P4）｜ 周期：11 天 → **MVP 基础功能 + 参赛 PPT**；随后持续迭代

---

## 0. 两阶段定位（重要）

```
阶段 A · MVP（11 天）
  交付：功能完整的基础闭环 + 参赛 PPT
  原则：功能一个不少——视频识别、责任判定、应急方案、双端界面、RAG 全都要有；
        但视频识别「精度允许降低」（低精度基础方案实现），精度留到迭代阶段优化
  输入：行车记录仪视频（低精度基础识别）+ 事故照片 / 文字描述（补充/兜底）

阶段 B · 迭代（11 天后）
  交付：把「精度」与「广度」做上去
  范围：视频识别精度提升（轨迹重建/夜间/遮挡）、更全法条库、责任置信评估
```

> **核心原则：功能不砍，精度递进。** 11 天先做出功能齐全的闭环（哪怕视频识别靠基础方案），后续迭代只提升质量、不新增结构性缺口。详细论证见 `FEASIBILITY.md`。

## 1. 系统模块地图

| 编号 | 模块 | 一句话说明 | 承载端 |
|------|------|-----------|--------|
| M1 | 视频感知 / 场景理解 | 行车记录仪视频 → 目标检测（车/人/车道线/信号灯）+ 轨迹提取 + 事故瞬间关键帧 → 结构化场景（JSON） | 服务端 |
| M2 | 规则库 + 案例库（RAG） | 《道交法》及实施条例、地方细则、公开裁判文书 → 向量检索增强 | 服务端 |
| M3 | 责任判定智能体 | 场景要素 + 规则检索 → 责任认定（全责/主责/同责/次责/无责）+ 归属条款 + 判定理由 | 服务端 |
| M4 | 应急方案智能体 | 按事故类型即时生成处置清单（报警/警示牌/撤离/急救/保险报案/证据固定） | 服务端 |
| M5 | LangGraph 编排 + 后端 API | 编排 M1→M3/M4 的多智能体协同、状态管理、REST 接口 | 服务端 |
| M6 | Web 双视角前端 | 车主端（上传→应急+责任预判）、交警端（责任辅助认定→认定书草稿+证据清单） | 前端 |
| M7 | 演示视频 + 评测 | 真实行车记录仪样本、判定口径评测 | 全队 |

### 数据流

```
车主/交警上传视频
   → M1 视频感知（检测+轨迹+关键帧 → 场景 JSON）
   → M2 RAG 检索（相关法条 + 相似案例）
   → M3 责任判定智能体（要件分析 → 责任认定 + 依据）
   → M4 应急方案智能体（按事故类型生成处置步骤）  // 并行于/随 M3 输出触发
   → M5 编排汇总 → M6 前端呈现（判定过程 + 证据 + 应急清单）
```

## 2. 四角色职责

### P1 · 队长 / 产品 + 业务
- 需求冻结、界面流程定义（车主/交警各一条主流程）
- **M2 业务侧**：整理《道交法》《实施条例》、常见事故类型的要件清单与责任归属口径
- 收集 8–12 个**公开典型案例**作为 RAG 种子数据（统一标注责任结论）
- 定义**评测口径**（哪些场景必须判对）、撰写演示脚本
- 答辩主讲、组委会沟通

### P2 · 后端 / 架构
- **M5**：LangGraph 状态图设计（State Schema、节点与条件边）、多智能体调用编排
- 后端 REST API（上传、任务状态轮询/WebSocket、结果查询）、异步任务队列
- **M2 服务侧**：向量库（如 chromadb/faiss）搭建与检索接口
- 对接 MoMA 平台模型网关（LLM 与视觉模型调用地址、鉴权、配额）
- 定义**模块间 JSON 接口契约**，供 P3/P4 并行开发

### P3 · 算法 / 核心智能
- **M1**：视频检测（YOLO 系列 + 追踪如 ByteTrack）→ 轨迹 / 碰撞点 / 关键帧；事故瞬间检测
- **M3**：责任判定智能体的提示词工程与推理链（要件分解 → 比对规则 → 出结论）
- **M4**：应急方案生成的规则 + LLM 结合逻辑
- **M2**：法条/案例的切分、Embedding、入库
- 提供**场景 JSON 标准结构**（这是 M1→M3 的接口，必须先定）

### P4 · 前端 / 全栈
- **M6**：车主端（上传、进度、结果卡片、应急步骤）+ 交警端（案件列表、责任认定详情、证据清单、认定书草稿导出）
- 视频可视化：检测框叠加、时间轴、关键帧回放、责任原因标注
- 与 P2 的 API 联调；移动端适配（行车记录仪场景车主常用手机）
- UI 上架素材、演示录屏

## 3. 并行策略与依赖

| 并行支线 | 依赖 | 起点 |
|----------|------|------|
| P3 视频感知（M1，低精度版） | 需先定「场景 JSON 结构」 | Day 1 |
| P2 编排 + API（M5） | 需接口契约；可先用 mock 场景 JSON | Day 1 |
| P4 前端（M6） | 需 API 契约；先搭骨架 + mock 数据 | Day 1 |
| P1 规则/案例/M2 数据 | 独立 | Day 1 |

**关键：Day 1 必须先定两个契约**，否则四人不并联：
1. 场景 JSON Schema（P3 出）→ 决定 M5/M6 如何消费
2. API 接口契约（P2 出）→ 决定 P4 如何联调

> 视频识别在 MVP 阶段为**低精度基础实现**（关键帧抽帧 + 基础检测 → 场景 JSON），供完整闭环演示；精度提升（多车轨迹重建、夜间/遮挡处理）全部归入迭代阶段 B。

| D2 | 管道打通 | 首批典型案例 4 个入账 | LangGraph 节点占位(mock)→串联；上传/轮询接口 | 视频 → 场景 JSON（低精度版）可用 | mock 数据渲染双端页面 |
| D3 | 感知完成(低精度) | 要件清单 v2（覆盖 8 类事故） | RAG 检索接口 + 法条入库；任务队列 | 抽帧+基础检测+关键帧 → 场景 JSON 完整 | 视频检测框叠加组件 |

| D5 | 应急上线 | 应急流程合规性核对 | M4 节点；WebSocket 进度 | **应急方案智能体 v1**（按类型出步骤） | 车主端结果卡片+应急步骤高亮 |
| D6 | 全链路打通 | 端到端试跑，记录问题 | 全链路（M1→M3→M4）无 mock 跑通 | 判定/应急边界修整 | 交警端列表+责任详情初版 |
| D7 | 交警端完整 | 制定 2 个演示场景 | API 完善、错误处理、鉴权 | 责任书判定理由结构化输出 | **交警端完整**：证据清单+认定书草稿 |
| D8 | 联调+评测 | 跑评测集，回归判定口径 | 性能优化、并发、日志 | 按评测结果调判定逻辑 | 移动端适配 + 时间轴/关键帧回放 |
| D9 | 稳定 | 演示脚本定稿 | 部署环境（服务打包/启动脚本） | 低精度感知容错（识别不出 → 回调文字补录） | 交警端导出（PDF/截图）；UI 打磨 |
| D10 | 彩排 | 全流程彩排 + 记录 | 稳定性加固、文档 | 感知失败降级链路（自动转文字描述输入） | 演示录屏 + 上架素材 |
| D11 | 冻结 | **答辩材料 + PPT 定稿** | 交付包核对、环境复现 | 视频演示集最终确认 | 演示视频最终成品 |

> 里程碑验收口径（每个都"能看得到"，MVP 阶段功能齐全）：
> - D3：一段真实视频 → 输出场景 JSON + 检测框截图（**低精度版 M1 成立**）
> - D6：一个真实视频 → 完整输出责任认定 + 应急方案（**多智能体闭环成立**）
> - D8：输入以下任一方式都能出完整结果（**功能不砍**）：视频 / 照片 / 文字描述
> - D11：三个演示场景全程可控 + 参赛 PPT 定稿（**可交付、可答辩**）

  "video_id": "case_001",

    {"id": 1, "type": "car", "trajectory": [{"t": 0.0, "x": 0.5, "y": 0.3, "speed_kmh": 48}, {"t": 12.4, "x": 0.6, "y": 0.32, "speed_kmh": 41}]}

## 6. 风险与降级（原则：功能不砍、精度递进）

| 风险 | 影响 | 处理方案 |
|------|------|----------|
| MVP 视频识别精度低（夜间/遮挡） | M1 输出不稳定 | 识别精度**允许降低**，但功能保留；感知失败自动回调「文字补录现场要素」，判定/应急仍完整 |
| 视频模型 Token/算力配额受限 | 全帧识别成本高 | M1 用**关键帧抽帧** + 本地基础检测，仅 LLM 走平台 |
| 责任判定做不到 100% 准 | 公安正式认定 vs 辅助建议 | 定位为**辅助研判建议** 而非裁决，输出置信度与理由 |
| RAG 案例不足 | 检索效果弱 | 以**法条要件规则**为主、案例为辅，规则兜底 |

> 对齐团队原则：**「功能一个不少，精度逐步提升」** —— 11 天交付功能齐全的闭环，视频感知精度不足通过降级路径（文字/照片补录）兜底，把精度优化留给迭代阶段 B；多智能体判定/应急/双端界面在任何输入方式下都完整成立。
