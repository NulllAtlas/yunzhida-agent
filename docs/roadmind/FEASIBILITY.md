# RoadMind · 可行性核定（FEASIBILITY REVIEW）

> 版本：v1.2（2026-09-26）
> 核定对象：**4 人 × 11 天**，产出**功能完整的基础闭环（MVP）+ 参赛 PPT**；功能一个不少（含视频识别），仅视频识别**精度允许降低**，精度在 11 天后持续迭代提升。
> 结论先行：**可行（7.5/10）**。核心策略是 **「功能不砍，精度递进」** —— 11 天做出功能齐全的闭环（视频识别用低精度基础方案），后续迭代只做「精度与广度」的提升，不新增结构性缺口。

---

## 1. 定位与两阶段策略

> 本方案是参赛作品，**11 天主交付物 = 功能完整的基础闭环 + 参赛 PPT**。可行性判断标准 = **能否在 11 天做出"功能齐全、站得住、讲得清、能演示"的作品，同时给精度提升留出迭代空间**。

```
阶段 A · MVP（11 天）
  目标：功能完整闭环可运行 + 参赛 PPT 完成
  原则：功能一个不少 —— 视频识别、责任判定、应急方案、双端界面、RAG 全要有
  输入：行车记录仪视频（低精度基础识别）+ 事故照片 / 文字描述（补充/兜底）
  视频识别：允许低精度，用关键帧抽帧 + 基础检测实现

阶段 B · 迭代（11 天后，持续）
  目标：把「精度与广度」做上去
  能力：视频识别精度提升（多车轨迹重建、夜间/遮挡）、更全法条库、责任置信评估
```

**关键认知**：阶段 A 与阶段 B 是**同一作品的连续演进**。阶段 A 保证**功能齐全**（不砍任何卖点），阶段 B 只负责**变准变广**。PPT 同时展示"已实现的功能闭环"与"清晰可行的精度提升路线图"。

---

## 2. 阶段 A（MVP）可行性分项打分（1–10）

| 模块 | 可行性 | 依据 | 最大风险 |
|------|:-----:|------|----------|
| M1 视频感知（低精度版） | **7** | 关键帧抽帧 + 基础检测（YOLO）可跑通；不做高精度轨迹重建 | 精度低 → 用照片/文字补录兜底 |
| M2 规则库 + 案例 RAG（基础） | **9** | 法条公开、无需数据授权；P1 可整理 | 无，仅工作量 |
| M3 责任判定智能体 | **8** | LLM 要件推理成熟；吃结构化场景或文字描述 | 判错 → 靠"建议+置信度"化解 |
| M4 应急方案智能体 | **9** | 规则模板 + LLM 润色，不依赖视觉精度 | 低 |
| M5 LangGraph 编排 + API | **8** | LangGraph 成熟，mock 并联开发 | 11 天从零学，需 P2 上手快 |
| M6 Web 双端前端 | **7** | 常规 CRUD + 可视化 | 工作量集中，需 P4 强 |

> **MVP 平均 8 分**：功能齐全 + 精度递进的定位，让 11 天工作量落在"一条完整闭环 + 界面 + 低精度感知"，**完全在 4 人 11 天能力范围内**。

## 3. 视频识别：保留功能，降低精度

### 3.1 MVP 阶段（D1–D11）—— 低精度、功能在

| 环节 | MVP 实现（低精度） | 迭代版（阶段 B） |
|------|--------------------|------------------|
| 检测 | 关键帧抽帧 + 基础检测（YOLO）识别车辆/行人/信号灯 | 多目标 + 轨迹重建 |
| 碰撞判断 | 用画面重叠/速度骤变近似 | 精细碰撞重建 |
| 场景输出 | 基础场景 JSON（车/人/要素） | 高置信场景 JSON |
| 兜底 | 识别置信低 → 自动回调文字/照片补录 | 多视角融合 |

### 3.2 为什么"降低精度"而非"砍功能"
- 11 天内把视频识别功能**完整做出并接入闭环**是可行的；把精度调到高水准则不可行。
- 把 **识别精度** 与 **业务功能** 解耦：功能（能识别并驱动判定）在 MVP 交付，精度（识得准）迭代优化。
- 这保留了卖点，也不拖累 11 天交付，符合"功能不砍、精度递进"原则。

### 3.3 数据 / 合规提示
- 真实行车记录仪**事故**视频获取难、涉隐私。MVP 用**公开/合成演示视频 + 预设 demo 数据**演示；真实数据在迭代阶段按合规流程接入。

---

## 4. 资源可行性（11 天）

- **4 人 × 11 天 ≈ 44 人日**，投入功能齐全的 MVP（感知低精度版 + RAG + 判定 + 应急 + 编排 + 双端）约 34–38 人日，**够用，富余用于演示打磨与 PPT**。
- **技能栈**：P2 需 LangGraph/FastAPI，P4 需 Vue/React，P3 需会基础 CV（YOLO 跑通）+ LLM 推理链。
- 若 P3 CV 基础弱：用**现成预训练 YOLO** + 抽帧即可出低精度结果，不要求自训练模型。

---

## 5. 建议路线

1. **MVP 必保（功能齐全）**：视频（低精度）→ 场景 JSON → 责任判定智能体（RAG 法规+案例）→ 应急方案 → 双端界面 → 编排闭环；照片/文字作为补充与兜底输入。
2. **演示**：用 1–2 段公开/合成演示视频 + 用户可手动输入文字，现场稳定跑"输入 → 过程 → 结果"可视化。
3. **PPT**：展示"功能齐全的闭环已实现（含视频识别）+ 具体的精度提升路线图"。
4. **迭代（11 天后）**：按路线图逐项提升视频识别精度、扩充法条库、加置信评估。

---

## 6. 决定树

```
主目标：11 天做一个"功能齐全"的参赛作品（PPT + 完整闭环）
 ├─ 既保留全部功能、又要求高精度 → 不可行（精度是迭代优化的）
 └─ 功能不砍、精度递进（MVP 低精度 + 迭代提精度）→ 可行性 7.5/10 ✅
     ├─ 视频识别：低精度实现，功能在 → 保留卖点
     ├─ 照片/文字补录：作为兜底输入 → 演示稳
     └─ 精度优化放阶段 B → 后续持续交付
```
