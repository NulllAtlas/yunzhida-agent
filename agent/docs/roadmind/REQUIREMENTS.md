# REQUIREMENTS.md · 需求文档 v1（Day 1 · P1 队长）

> 版本：v0.1（2026-09-27，Day1）
> 目的：定义"要判什么、判对算什么"，保证方案贴合交警/车主真实场景，能说得清、能答辩。

## 1. 产品定位

云智达 是一套 **事故发生时任务紧急、事后可追溯** 的辅助研判工具：

- 对 **车主**：第一时间给到"该不该报警/叫救护车、现场怎么做"，降低二次事故与处置失当。
- 对 **交警**：把行车记录仪视频自动转成结构化的责任认定依据，辅助出认定书，提升效率。

> 定位边界：**辅助建议**，输出置信度 + 理由，标注"仅供参考"，**不替代**交警最终认定。

## 2. 核心目标（可判定）

| 目标 | 衡量方式 |
| --- | --- |
| 功能闭环 | 视频 → 场景 → 判定 → 应急 → 前端展示，任意输入都能出结果 |
| 责任预判可用 | 责任占比 + 理由分条 + 置信度 + 法条引用 |
| 应急可用 | 按事故类型给分步动作 + 紧急度标签 |
| 交警可导出 | 认定书草稿文本生成 |

## 3. 车主主流程

```
打开网页(/owner)
  → 上传行车记录仪视频
  → 系统解析（感知/检索/判定）
  → 「是否立即需拨 120/122」级联提示
      ├─ 是（伤亡/起火/严重）→ 红色弹层：拨打 120/122
      └─ 否 → 普通处置建议
  → 应急处置步骤（分步、可勾选）
  → 责任预判概览（责任占比 + 置信度 + 理由）
  → （可选）补录文字/照片（当视频识别置信低）
```

**关键交互要求**
- 事故瞬间的"立即处置"必须强提示（红色弹层，如撞人 → 拨 120）。
- 应急步骤分步引导，支持勾选完成。
- 移动端优先适配（行车记录仪事故场景车主常用手机）。
- 识别置信低时自动转"文字/照片补录"，保证任何输入都出结果。

## 4. 交警主流程

```
打开网页(/police)
  → 登录（车主/交警角色）
  → 案件列表（GET /cases）
  → 选择/上传案件
  → 查看责任认定详情
      ├─ 责任占比（如 70/30）
      ├─ 法条依据
      ├─ 理由分条（reasoning）
      ├─ 证据清单（关键帧 + 检测框 + 事件时间戳）
      └─ 场景置信度
  → 导出认定书草稿（GET /case/{id}/export）
```

## 5. 三类典型用例

### 用例 1：追尾
- **场景**：A 车在路口因前车急刹，B 车未保持安全距离追尾 A。
- **处置**：是否拨 120 → 视伤亡；应急 → 设三角牌/撤离。
- **责任倾向**：B 车（后车未保持安全距离）全责/主责。
- **要件**：追尾 = 后车未保持安全距离 / 前车无突然倒车等异常。

### 用例 2：路口抢行
- **场景**：无信号灯路口，A 车未让右方来车 B，两车相撞。
- **处置**：视伤亡拨 120；应急流程。
- **责任倾向**：未让行方 A 主责/全责。
- **要件**：让行义务（让右 / 让直行 / 转弯让直行）。

### 用例 3：车撞行人
- **场景**：机动车在未避让行人的路段（如斑马线）撞到行人。
- **处置**：**优先拨 120**（最高紧急度），保护现场。
- **责任倾向**：机动车主责（人行横道未减速/未让行），行人闯灯则视情分担。
- **要件**：路口/斑马线让行义务、行人过错认定。

## 6. 判定口径（Day1 初版，与 P3 对齐）

- 输出 **责任占比**（主/次/同等），而非"是谁全责"的孤立结论。
- 每项结论给出 **理由分条** 与 **法条引用**。
- 附 **置信度**；拿不准 → 标低置信并提示人工复核 / 转文字补录。
- 责任倾向随 RULES.md（D2）细化。
